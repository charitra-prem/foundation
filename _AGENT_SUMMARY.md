OTA updates are now wired up via `expo-updates` (v56.0.19) and EAS Update. `package.json` adds `expo-updates` as a dependency; `app.json` gains an `updates` block (URL, `checkAutomatically: ON_LOAD`) plus a `fingerprint` runtimeVersion policy and an `extra.eas.projectId` placeholder — both the URL and project ID must be replaced with real values after running `eas init`. A new `eas.json` defines three build profiles (`development`, `preview`, `production`) each with the appropriate EAS Update channel. `src/app/_layout.tsx` now consumes `Updates.useUpdates()` and calls `Updates.reloadAsync()` whenever `isUpdatePending` becomes true, so a downloaded update is applied immediately on the next splash-screen cycle. Two new tests in `src/app/__tests__/ota-updates.test.tsx` verify that `reloadAsync` is not called when no update is pending and is called exactly once when one is; all 7 tests pass and `tsc --noEmit` is clean.
