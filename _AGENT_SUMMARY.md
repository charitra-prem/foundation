## AIO-18: Sentry Error Tracking + TipTap Editor Port

Added two foundation integrations for the Expo React Native app. **Sentry** (`@sentry/react-native@7.11.0`) is initialised at module level in `src/app/_layout.tsx` via `Sentry.init()`, with the root layout wrapped in `Sentry.wrap()` for automatic error boundary and session tracking; the Expo config plugin (`@sentry/react-native/expo`) is registered in `app.json`, and a `metro.config.js` wires in `getSentryExpoConfig` for automatic source-map upload during builds. The Sentry DSN is read from `EXPO_PUBLIC_SENTRY_DSN` so it stays out of source control. **TipTap** does not have a native React Native port, so `src/components/TipTapEditor.tsx` renders the full TipTap web editor inside a `react-native-webview@13.16.1` WebView, loading `@tiptap/core`, `@tiptap/starter-kit`, and `@tiptap/extension-placeholder` from `esm.sh`; bidirectional communication between the editor and the host app is handled via `postMessage`, with `onUpdate`, `editable`, `content`, `minHeight`, and `placeholder` props. Tests in `sentry.test.tsx` and `tiptap-editor.test.tsx` cover Sentry initialisation (mocked `Sentry.init`/`Sentry.wrap` calls) and TipTap editor rendering (mocked WebView); all 11 tests pass and TypeScript reports zero errors.
